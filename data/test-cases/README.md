# Test Cases Data

Ця папка містить JSON-файли з бібліотекою тест кейсів для QA Test Constructor.

## JSON-схема тест кейсу

Кожен тест кейс повинен містити всі 9 полів у такому порядку:

```json
{
  "ID": "TC-{PREFIX}-{NUM}",
  "Назва": "Дієслово + іменник без префіксів",
  "Suite": "Назва модуля",
  "Передумови": "Умови перед тестом з плейсхолдерами для даних",
  "Кроки": [
    "1. Дія користувача",
    "2. Дія користувача"
  ],
  "Очікуваний результат": "Детермінований спостережуваний результат",
  "Type": "E2E | Manual",
  "Layer": "Smoke | Regression | Feature",
  "Пріоритет": "P0 | P1 | P2"
}
```

## Поля схеми

| Поле | Тип | Опис |
|------|-----|------|
| `ID` | string | Унікальний ідентифікатор кейсу у форматі `TC-{PREFIX}-{NUM}` |
| `Назва` | string | Дієслово + іменник, без слів-результатів («Успішна», «Коректне», «Валідація») |
| `Suite` | string | Назва модуля, до якого належить кейс |
| `Передумови` | string | Умови перед тестом; усі тестові дані — у плейсхолдерах `{curly_braces}` |
| `Кроки` | string[] | Пронумерований список дій користувача; верифікація — лише в «Очікуваний результат» |
| `Очікуваний результат` | string | Детермінований результат; без «може», «залежно від», «або» як розгалуження |
| `Type` | "E2E" \| "Manual" | Тип виконання тесту |
| `Layer` | "Smoke" \| "Regression" \| "Feature" | Шар запуску в CI |
| `Пріоритет` | "P0" \| "P1" \| "P2" | Критичність бага |

## Типи тестів (Type)

| Тип | Коли використовувати |
|-----|----------------------|
| `E2E` | Тестер проходить сценарій вручну у браузері. Використовувати за замовчуванням. |
| `Manual` | Потребує нативних дій пристрою або DevTools, які неможливо відтворити у браузері (камера, біометрія, інспекція `<meta>`-тегів, CAPTCHA). |

> `Unit`, `Component`, `Integration` — встановлюються лідом/розробником для автотестів.

## Шари тестів (Layer)

| Шар | Коли запускати | Обсяг |
|-----|---------------|-------|
| `Smoke` | На кожному деплої | 1–3 кейси на Suite, виконання < 30 сек. Лише найкритичніший happy path. |
| `Regression` | Перед релізом | Edge cases та перевірені сценарії. |
| `Feature` | Нова функціональність | Не переводити в Smoke до стабілізації. |

> Пріоритет ≠ Шар. Пріоритет = критичність бага. Шар = коли запускати.
> Приклад: новий критичний флоу → P0 + Feature (не Smoke, поки нестабільний).

## Пріоритети (Пріоритет)

| Рівень | Визначення |
|--------|-----------|
| `P0` | Блокує бізнес-операції: авторизація, оплата, оформлення замовлення. |
| `P1` | Основні робочі флоу: списки, фільтри, навігація, ключові сторінки. |
| `P2` | Другорядні сценарії: UX-полірування, рідкісні кейси, косметика. |

## Конвенції тестових даних

Усі тестові дані — плейсхолдери у фігурних дужках:

| Замість | Використовувати |
|---------|----------------|
| `«ЗНИЖКА10»` | `{valid_coupon_code}` |
| `test@example.com` | `{registered_email}` або `{invalid_email_format}` |
| `500 грн` | `{min_order_amount}` |
| `«xyzqwerty»` | `{nonexistent_search_query}` |
| `< 5 МБ` | `{max_file_size}` |
| Будь-яке ім'я | `{user_name}` |

## ID-префікси модулів

| Префікс | Модуль |
|---------|--------|
| `TC-CAT` | Каталог товарів |
| `TC-PDP` | Сторінка товару (Product Detail Page) |
| `TC-CART` | Кошик |
| `TC-CHK` | Checkout (Оформлення замовлення) |
| `TC-AUTH` | Авторизація / Особистий кабінет |
| `TC-SRCH` | Пошук |
| `TC-BLOG` | Блог |
| `TC-FORM` | Контактна форма |
| `TC-LANG` | Багатомовність |
| `TC-CPN` | Купони / Промокоди |

## Конвенції

- JSON-файли зберігаються у цій папці (`/data/test-cases/`)
- Редагування файлів не потребує перекомпіляції застосунку (GEN-01)
- Нові файли підхоплюються лоадером `src/lib/test-cases.ts`
- Форматування: UTF-8, відступи 2 пробіли
