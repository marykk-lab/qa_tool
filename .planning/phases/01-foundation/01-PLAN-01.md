<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build/dev toolchain → repo | npm packages pulled during scaffold execute arbitrary install scripts |
| repo → Vercel platform | source + any config (env vars) is uploaded to a third-party build/host |
| JSON data file → rendered DOM | `data/test-cases/*.json` content is interpolated into the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SC | Tampering | npm install (Next.js, Tailwind, deps) | mitigate | Use only official packages (`next`, `react`, `react-dom`, `tailwindcss`, `postcss`, `autoprefixer`, `typescript`, `@types/*`) installed via `create-next-app` defaults; no third-party UI libs added in this phase. Any non-official package would require a blocking-human legitimacy checkpoint, but none are introduced here. |
| T-01-01 | Information Disclosure | Vercel config | mitigate | No secrets/env vars exist in this phase (`env_vars: []`). `.gitignore` MUST exclude `.env*`, `.vercel`, and `node_modules` so no credentials or local Vercel link tokens are committed. |
| T-01-02 | Tampering (XSS) | TestCaseCard rendering of JSON content | accept | JSON is author-controlled (committed by the QA team, not end-user input) and React escapes interpolated strings by default. No `dangerouslySetInnerHTML` is used. Risk is low for v1; revisit when/if user-supplied content is introduced. |
| T-01-03 | Spoofing | Vercel deploy | accept | Deploy uses the developer's authenticated Vercel session via a blocking human checkpoint; no automated tokens stored in repo. |
</threat_model>
